# Architecture Audit — 2026-09-20

## Scope

Architecture review for Sakhalin Kids Studio after evaluating the current project stack and external open-source services.

This audit records decisions only. It does not claim that the documented integrations are already implemented.

## Decisions accepted

### 1. Production execution role

OpenMontage remains the production framework and state owner.

A separate Production Director role is required to execute pipeline instructions, tools, artifacts, and checkpoints.

OpenCode may temporarily fulfill this role interactively for early proof work, but development and production permissions must remain conceptually separate.

### 2. OpenMontage upstream

OpenMontage must be pinned to an explicit commit.

Current reference baseline:

```text
08e2151fa02de28a5d6a312b3d575692bf147ad7
```

Do not silently track upstream `main`.

Before upgrading, compare schema/tool contracts and rerun the Character Runtime proof.

### 3. Pipeline manifest compatibility

The pinned OpenMontage manifest schema accepts:

```text
production
beta
```

for pipeline stability.

The Sakhalin pipeline was updated from:

```yaml
stability: experimental
```

to:

```yaml
stability: beta
```

The pipeline also references Sakhalin-specific tools, so `extensions.custom_tools` is now enabled.

This does not mean the pipeline is executable yet; referenced custom tools and director skills still need implementation.

### 4. Asset lifecycle

Approved production assets require:

- stable IDs;
- explicit versions;
- checksums;
- provenance;
- rights metadata;
- dependency tracking;
- approval binding.

Approved assets are never silently overwritten.

Episode revisions pin exact asset versions.

### 5. Storage model

Logical storage is split into:

- Git for code/metadata/small fixtures;
- durable media storage for approved masters and original assets;
- workspace/cache for reproducible temporary artifacts.

S3-compatible object storage is an approved future option, not a current mandatory dependency.

### 6. Backup and restore

Backups are not considered sufficient until a restore drill succeeds.

restic is an approved candidate tool, not a current dependency.

### 7. Job execution

Long-running/paid operations need:

- job IDs;
- attempts;
- idempotency;
- explicit external provider request IDs;
- bounded retries;
- resume;
- cancellation;
- per-attempt cost accounting;
- explicit unknown external state.

Milestone 01 may remain single-process and sequential.

PostgreSQL is the preferred future durable job/state store only when multi-worker or control-plane requirements justify it.

### 8. ComfyUI

ComfyUI is approved as a future controlled media worker.

It should use curated/versioned workflows.

Production agents must not install arbitrary custom nodes or execute unreviewed workflow graphs during a production run.

ComfyUI is not required for Milestone 01.

### 9. Russian alignment

WhisperX is approved as a candidate to evaluate for Russian speech alignment.

It is not a replacement for the project viseme model and is not a Milestone 01 dependency.

A pronunciation dictionary and human listening review are required for recurring names/toponyms/terms.

### 10. Editable delivery

OpenTimelineIO is approved as the preferred future interchange model for editable timing/clip references.

The actual NLE round-trip must be tested before relying on OTIO for all effects/transitions.

Manual finishing is explicitly supported.

### 11. Technical media QA

FFmpeg/ffprobe should provide deterministic checks for:

- stream presence;
- duration;
- resolution/frame rate;
- black segments;
- silence;
- clipping/loudness;
- sample frames.

Technical PASS does not equal creative approval.

### 12. Editorial architecture

Every episode should eventually have an explicit editorial contract including:

- target age/audience;
- educational objective;
- central question;
- discovery/answer;
- safety considerations;
- expected runtime.

Material educational claims must be linked to sources through a claims ledger.

### 13. Publishing

YouTube publication remains manual-first.

Before future automation, current official platform rules must be reverified for:

- Made for Kids settings;
- children's-content feature limitations;
- synthetic/altered-media disclosure;
- upload/API fields.

### 14. Hermes

Hermes remains a future operator/control-plane layer after the first proof.

It must interact through narrow MCP/API operations and cannot own a competing production state machine.

### 15. DeepSeek Harness

DeepSeek Harness remains a future bounded cognitive layer for:

- research;
- script review;
- factual QA;
- production QA.

It is not part of the first production critical path.

### 16. Paperclip

Paperclip may later manage project-level goals/tasks/budgets.

It must not duplicate per-scene production state owned by Sakhalin Kids/OpenMontage.

### 17. Langfuse

Langfuse is a later observability candidate after real agent/model runs exist.

It is not the financial source of truth and is not a current dependency.
